# EXTENSION.md — apps/extension

Chrome **Manifest V3** extension built with **WXT** + React + TypeScript. Main UI is a **side panel**. Shares `packages/ui` and `packages/shared` with the website. UI rules: `DESIGN.md` → *Extension side panel*.

## Responsibilities

- Extract the article from the active tab (on demand).
- Run on-device AI via Firebase AI Logic (gatekeeper, summary, graph check, Ask).
- Call the API for retrieval / cloud checks / follows.
- Show status, changes, sources (+ Google Search suggestions), Follow, "Open full explainer" (→ website).
- Badge the toolbar icon when a followed story updates.

## Entry points (`apps/extension/entrypoints/`)

| File | Kind | Does |
|---|---|---|
| `background.ts` | service worker | `sidePanel.setPanelBehavior({ openPanelOnActionClick: true })`; `alarms` (30 min) → `GET /v1/follows` → badge; message router |
| `sidepanel/index.html` + `App.tsx` | extension page | The whole UI; owns Firebase app, auth, AI Logic, App Check |
| `extractor.ts` | unlisted script (bundled) | Injected with `chrome.scripting.executeScript`; runs Readability on a cloned DOM; returns `ExtractedArticle` |
| `options/` | optional | Settings (or reuse side panel settings view) |

No always-on content script (ADR-012).

## Manifest (generated by `wxt.config.ts`)

```ts
export default defineConfig({
  modules: ["@wxt-dev/module-react"],
  manifest: {
    name: "ThreadNews — is this article still true?",
    description: "Checks if a news story has moved on since the article you're reading. On-device AI first.",
    key: "<base64 public key — keeps the extension ID stable for OAuth + Auth domains>",
    permissions: ["sidePanel", "activeTab", "scripting", "storage", "alarms", "identity"],
    optional_host_permissions: ["https://*/*", "http://*/*"],          // asked at runtime, with explanation
    host_permissions: ["https://threadnews-api.vercel.app/*"],
    side_panel: { default_path: "sidepanel.html" },
    action: { default_title: "ThreadNews" },
    oauth2: { client_id: "<chrome-extension OAuth client id>.apps.googleusercontent.com",
              scopes: ["openid", "email", "profile"] },
    content_security_policy: { extension_pages: "script-src 'self'; object-src 'self'" },
    minimum_chrome_version: "148",
  },
});
```

### Permissions explained (for the store listing & judges)
- `activeTab` + `scripting`: read the article you're viewing when you open ThreadNews.
- **Optional** "read sites you visit": lets ThreadNews re-check automatically when you switch tabs while the panel is open. Requested in-panel with a clear explanation; everything works without it (user clicks "Check this page").
- `storage`: settings + offline story cache. `alarms`: check followed stories. `identity`: Google sign-in. `sidePanel`: the UI.

## Article extraction (`extractor.ts`)

```ts
type ExtractedArticle = {
  url: string; canonicalUrl?: string; title: string; publisher?: string;
  publishedAt?: string;           // JSON-LD datePublished → meta article:published_time → <time datetime>
  lang?: string;
  text: string;                   // Readability textContent, trimmed to ~24k chars (≈6k tokens)
  isProbablyArticle: boolean;     // Readability isProbablyReaderable + og:type=article
};
```
The text stays in the side panel's memory only. It is never written to storage or sent to our API.

## Side panel architecture

```
sidepanel/
  App.tsx                  providers (Query, Auth, RC, Theme) + router (main | settings | ask)
  firebase.ts              initializeApp; App Check (debug token, CustomProvider — no remote script);
                           getAuth from "firebase/auth/web-extension"; firestore; remote config; ai
  hooks/
    useActiveTab.ts        current tab id/url; listens to tabs.onActivated/onUpdated when permitted
    useExtract.ts          executeScript(extractor) → ExtractedArticle
    useOnDevice.ts         LanguageModel.availability(), initialize (button), progress
    useCheckFlow.ts        same state machine as the website (shared in packages/shared/flow)
    useFollow.ts           POST/DELETE /v1/follows, onSnapshot of followed story
  views/                   Main, Settings, AskSheet
```
`useCheckFlow` and `CheckViewModel` are shared with the website — keep logic in `packages/shared/flow`.

### Flow on panel open / tab change
1. `useExtract` → `ExtractedArticle` (or "This page doesn't look like an article").
2. Gatekeeper + summary on-device (parallel).
3. `needsCheck` → `/v1/graph/retrieve` → fresh ? on-device graph check : `/v1/check`.
4. Render; write on-device results to `users/{uid}/checks`.
5. Cache last 20 results per URL hash in `chrome.storage.session` (instant re-open).

## Auth

- Bootstrap: anonymous sign-in on first panel open.
- "Sign in with Google": `chrome.identity.getAuthToken({ interactive: true })` → `GoogleAuthProvider.credential(null, token)` → `linkWithCredential` (fallback `signInWithCredential` if the account exists). Code: `docs/architecture/04-auth-and-quotas.md`.
- Setup:
  1. Generate a key pair; put the public key in `manifest.key` → stable extension ID.
  2. Google Cloud console (same project) → OAuth client **Chrome Extension** with that ID → `oauth2.client_id`.
  3. Firebase Auth → Authorized domains → add `chrome-extension://<EXTENSION_ID>`.
- Service worker reads the persisted user via `firebase/auth/web-extension` to call `/v1/follows` on alarms.

## App Check

reCAPTCHA can't load in an extension page without remote code, so the judge build uses the **debug provider**: set `self.FIREBASE_APPCHECK_DEBUG_TOKEN = import.meta.env.WXT_APPCHECK_DEBUG_TOKEN` before `initializeAppCheck`, with a `CustomProvider` that never loads remote scripts. Register the token in Firebase console. **Revoke after Dec 16.** (Day-1 spike: confirm no remote script is fetched.)

## Offline story cache

For followed stories, store the packed **device-budget local context** (from `/v1/graph/retrieve`) in `chrome.storage.local` keyed by `storyId` (+ `lastUpdatedAt`). When offline, the on-device graph check uses it. Max 50 stories, LRU.

## Badge & updates

- `alarms.create("follows", { periodInMinutes: 30 })` → `GET /v1/follows` → count `unread` → `action.setBadgeText({ text: "1" })`, badge color = `--status-moved`.
- Opening a followed story's article clears its unread flag (`lastSeenEventId`).
